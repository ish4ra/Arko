# Architecture

Arkiv is a macOS 13+ AppKit application built with Swift Package Manager. `ArkivApp` owns native windows, menus, toolbars and an `NSTableView`. `ArkivCore` exposes an `ArchiveEngine` protocol, immutable catalog snapshots, folder indexing, progress and cancellation. `CArkiv` controls safe I/O and libarchive operations; `CArkivSeven` bridges a bundled 7-Zip library through descriptor-based callbacks. Neither app nor engine launches a shell or external compressor.

Archive operations run on a serial background queue per window. The C cancellation token is atomic; callbacks are synchronous and UI progress is throttled. A snapshot records source identity, size, and modification time; extraction rechecks these plus the entry catalog and refuses changed archives. The browser index creates implicit folders from the catalog. 7z inspection first decodes to a private ZIP spool; other formats enumerate without full extraction. Per-entry IDs are ordinals within that snapshot, not filenames, so selection is unambiguous for duplicate records.

Extraction writes to a private sibling staging directory, with a 100,000-entry/20-GiB budget. Successful output is moved to a new UUID-named directory; failures remove staging. Extraction has no overwrite mode. Explicit ZIP additions use a separate [transactional rewrite API](zip-additions.md). Backend registration is limited to ZIP, TAR, 7z and RAR/RAR5, with no external-program filter fallbacks. Format support claims follow fixtures, not registration.

System libarchive handles ZIP/TAR/RAR. A pinned, separately replaceable 7-Zip library handles 7z creation and AES-256 read/write; [source, patches, licensing and replacement](sevenzip.md) are documented. GUI and future CLI can share ArkivCore. No network services, accounts, telemetry, or runtime package managers.

Creation is exposed through ArchiveCreator with transactional verification/publication. Passwords are operation-local; unlocked snapshots retain only a private plaintext spool, not credentials. Mutation, preview workspaces and secure persistence/bookmarks remain deferred.

Finder selected-file Services are an AppKit adapter to `FinderRequest` and `FinderExtractor` in ArkivCore. The existing engine performs inspection/extraction unchanged; a C helper publishes verified staged output using fd-relative atomic no-replace moves. The app owns destination selection, progress, cancellation, and recovery UI. The sandboxed Finder Sync extension also hands allowlisted actions to the app through the existing custom URL scheme; no password or output path is transported.
